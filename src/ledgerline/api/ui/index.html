01.

Score a transaction

Send a real transaction from the held-out test set, which the model never trained on. The API fetches the card's history from Postgres, runs the same feature code used in training, and returns a score. Flags come with their reasons.

02.

Categorize a descriptor

Raw bank text in, one of 17 categories out. Gemini answers when it can; if it times out or errors, a local TF-IDF model answers instead, and the response says which one did.

03.

Audit trail

Every decision is written to Postgres with its input hash, score, threshold and model version before the response leaves. If that write fails, the API returns 503 rather than an unrecorded decision.

04.

System

One request, end to end. Offline training and this service share one feature implementation; a parity test proves their scores match to within 1e-9.

  1. Validate

    Schema generated from the model's own feature list. Bad input is a 422 naming the field, never a 500.

  2. History

    The card's earlier transactions, from Postgres.

  3. Features

    The same functions used in training: velocity, time since previous, amount vs card average.

  4. Score

    LightGBM, pinned by version. Reasons computed only for flags.

  5. Audit

    Decision recorded before the response is sent.
